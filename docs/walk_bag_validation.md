# 09-03-walkのカクつき・位置飛び検証

## 条件

2026-09-27、`/home/lambda/bag_files/09-03-walk` の全区間を通常速度で再生。
競技フィールド内・決勝bagと同じMID360取り付けとのユーザー確認を反映。
CustomMsg入力、use_sim_time=true、RVizはxcb/OpenGL・Fixed Frame=map。
取り付けはbase_linkからxyz=(0.2,-0.25,1.09)m、rpy=(3.13,-0.273,0)rad。
絶対位置の正解ラベルはないため、配信件数を位置精度とは扱わない。

## 実測した原因

- bag約105.6秒にLiDAR500件、IMU2119件。全区間平均では約4.7Hzと20.1Hz。
- LiDAR取得時刻の間隔は中央値0.100秒、p95=0.700秒、最大2.100秒。
- IMU取得時刻の間隔は中央値0.00588秒、p95=0.220秒、最大1.146秒。
- LiDAR記録時刻の間隔は中央値0.000358秒、最大2.941秒。通常再生では点群がまとめて届く。
- 取得時刻は記録時刻より約13–14秒古い。診断の観測年齢と収録遅延を分ける必要がある。
- 初期の全域探索はコスト約0.175–0.179で既定0.165を満たさず、約12秒後のスキャンで初めて採用された。単に表示用変換が遅いわけではない。
- 終盤のFAST-LIO `/Odometry` 自体が約0.1秒で1.5m以上動く区間があった。融合側はこれを取り込み、欠落/増分リセット後に全域探索で別位置を採用する経路もあった。

欠落とバーストはbag自体で確認した。これらがFAST-LIO崩壊の唯一の原因であることは未確定。

## 変更と結果

1. Header取得時刻で再生する `sensor_stamp_play.py` を追加。LiDAR500件・IMU2119件を内容・時刻を変更せず配信する。欠落を埋めない。
2. GN10と表示変換の受信キューを50件にし、マッチング1スキャンごとに運動/融合コールバックへ処理を戻す。
3. 3秒以内のオドメトリ欠落だけでは地図状態を消さない。ただし250ms超の内部欠落を点時刻補間しない。
4. 速度・角速度・床向きからの傾きを検査し、異常増分を取り込まない。正常3件の後も、新しい局所地図観測が成立するまでmap TFを止める。
5. 地図観測から既定1秒を超える予測はmap TFとして配信しない。初期化後は事前姿勢不足を理由に全域探索へ戻らない。
6. 融合補正は共分散とは独立にXY 0.5m、yaw 0.35radで制限する。
7. RVizの2D Pose Estimateを `/initialpose` へ接続。既知の地図位置を明示的に指定できる。異常オドメトリ中は受け付けない。

通常のbag再生・旧実装では、マッチング採用171件、融合335件、融合位置の隣接変化は最大約16.0m/sだった。
取得時刻再生だけでは終盤ドリフトは解消せず、融合の最大隣接変化は約10.6m/sだった。
保護を含む修正版では、マッチング採用207件、融合219件、最大隣接変化は約4.3m/s。
マッチング処理時間は開発PCで中央値約11.2ms、p95約35.2ms。Jetsonでの実測ではない。

**連続した高精度推定は未達。** 修正版の最後の融合姿勢は元bag記録開始に対するヘッダー時刻で約65.68秒。
取得時刻再生開始からは約78.5秒に相当する。その後は地図観測が成立せず、map TFを配信しない。
終盤の位置飛びを「成功した自己位置推定」として表示し続ける動作は止めたが、最後まで連続表示できる結果ではない。
最大2.4秒の融合配信間隔も残る。正しい絶対位置・姿勢の精度は未検証。

FAST-LIOの間引きを0.5mから0.2mへ細かくする比較も改善せず、既定には採用していない。
連続失敗時だけ±0.6mを探索する比較でも復帰採用0件だったため、追加探索は採用していない。
FAST-LIO本体への補正入力や改造は行わず、標準Odometryを受け取る疎結合を維持。

## 検証

ビルドとCTest6件が通過。時刻順再生テストはCDRエンディアン、順序、欠落の保持を確認。
融合テストは大きい共分散でも遠い補正を拒否すること、2.1秒欠落での状態保持、明示的な地図初期化を確認。
ROSノードへの合成入力でも、RViz初期化、予測期限切れでの停止、異常移動の拒否、地図観測後の復帰を確認。

実機では、LiDAR/IMUの取得時刻の欠落とドライバからの配信遅延を先に計測する必要がある。
このbagから欠けたIMU観測を復元したり、表示の補間だけで正しい連続自己位置にしたりはできない。
