## 再生

launchとbagは別の端末で起動する。

```bash
ros2 launch gn10_pointcloud_localization fast_lio_fusion.launch.py use_sim_time:=true
```

```bash
ros2 bag play '/home/lambda/bag_files/地区大会/rosbagjetson1/rosbag2_2026_09_19-17_04_40/rosbag2_2026_09_19-17_04_40_0.db3' --clock --topics /livox/lidar /livox/imu
```

このbagには収録時の `/platform_constraint` 1,403件、`map → base_link` TF 1,403件、`base_link → livox_frame` 静的TFもある。全トピックを再生すると、launchが新しく配信する自己位置・TFと競合する。センサーだけを再生し、`--clock` でシミュレーション時刻を配信する。

## 初期位置について

`initial_pose_local_search=false` が既定なので、launchの初期座標(0,0)は局所探索の拘束には使われない。初回は設定済みの全域探索を行う。ただし、その範囲・0.30m格子・フィールドの対称性のため、開始位置が異なれば探索結果も変わり得る。「初期位置の違いは無関係」ではない。

## 観測

bagのLiDARは `sensor_msgs/PointCloud2` で、20k点前後/フレーム。bridgeが要求する `x,y,z,intensity,tag,line,timestamp` が揃い、点ごとのtimestampはヘッダー時刻から約0–100ms。bagの取り付けTFはlaunch設定と同じ位置・向きだった。

従来の初回探索範囲はXYが±5.25m/±5.70m。収録済みの初回位置は(-5.65, 6.00)mで、この範囲外だった。収録済み姿勢は正解ラベルではなく、この初回姿勢は他の時刻と不連続なので、これだけから真の開始位置は確定できない。

LiDAR/IMUだけを再生した従来設定では初回候補(0.47, 1.88)m、yaw -1.55rad、全点コスト約0.165で初期化。収録済み姿勢と同時刻1,402件を比べると、位置差中央値4.80m、方位差絶対値中央値3.13radだった。点群が対称側へ置かれた状態に対応する。

探索範囲をXYとも±6.40mにした短時間試験では、初回候補(-4.72, -1.88)m、yaw 1.59rad、全点コスト0.1557で初期化。同時刻606件の位置差中央値0.091m、方位差絶対値中央値0.016rad。収録済み姿勢を正解として扱うものではないが、同一スキャンの地図支持も増えた（従来の誤方位候補は支持516/3,830点、修正候補は支持1,213/3,830点）。

初回全域探索の格子は0.30m間隔のため、探索範囲の変更は候補の格子位置も変える。最初の位置が探索範囲外だったことだけが誤初期化の原因と断定せず、この格子の位相と対称形状も影響する。地図支持や旧出力との一致は、独立した絶対位置精度の証明ではない。
